英语背诵与学习软件（cat paw）

端侧离线 AI 英语背诵工具 · 2026 上海开源软件应用创新大赛 · 开源 AI 工具赛道

项目负责人：康容恺（上海师范大学） |  代码许可：Apache-2.0  |  文档日期：2026-09-26

一句话：把课文或试卷（打字、拍照、传 PDF 都行）丢进去，本机大模型自动提炼生词·词组·作文金句·搭配·语法， 按考纲 × CEFR × 学生历史掌握三层过滤生成背诵清单，再用默写 + SM-2 间隔复习闭环到长期记忆。 全程离线运行，学习数据不出机器。

一、项目背景与痛点

1.1 评价的指挥棒已经转向"用语言解决问题"

课程层面。《义务教育英语课程标准（2022 年版）》把课程目标定为语言能力、文化意识、思维品质、学习能力四方面核心素养，课程内容以主题为引领，由主题、语篇、语言知识、文化知识、语言技能、学习策略六要素构成；教育部在发布说明中对外语课程给出的实施要求是——"通过语言学习活动，帮助学生在体验中学习、在实践中运用、在迁移中创新"。《普通高中英语课程标准（2017 年版 2020 年修订）》更直接把课程目标从"综合语言运用能力"转向学科核心素养，其"语言能力"的官方定义是"在社会情境中，以听、说、读、看、写等方式理解和表达意义的能力"。

评价层面。教育部考试中心研制的《中国高考评价体系》确立"四翼"考查要求——基础性、综合性、应用性、创新性，其中应用性明确强调"学以致用"；该体系并首创性地把"情境"确立为考查载体，即"让学生在真实的背景下……运用必备知识和关键能力去解决实际问题"。评价理念也从"知识立意、能力立意"转向"价值引领、素养导向、能力为重、知识为基"。

题型层面（最直观的证据）。教育部考试中心在《2020 年全国高考命题评析》中说明，英语科"推出读后续写题型，创造性地将'阅读'与'写作'深度结合，深入考查学生的综合语言运用能力、思维能力和学习能力"，并"减少完形填空题量和分值，取消短文改错题，增加阅读理解和写作分值"。

地方层面。上海市教委公布的高考英语改革自 2025 届春考起实施："听力理解"从笔试中分离，并入"听说测试"一起上机考——笔试由 140 分调整为 115 分，听说测试由 10 分调整为 35 分；官方对这轮改革的定性是"对学生英语实际应用能力的考察"，并称"强调语言'听'和'说'的比例更高，哑巴英语已经成为过去式"。

这意味着：初高中英语考察的重心，已经不是"认不认识这个词、记不记得这条释义"，而是能不能在真实的语境里理解它、并在需要的时候把它用出来。

1.2 主流学习工具的两个缺口

市面上主流英语学习 App 的产品逻辑高度一致：给出词表 → 卡片式记忆 → 间隔重复提醒 → 游戏化维持打卡。它以"记住更多单词"为优化目标，但在应试与真实运用中留下了两个致命缺口。

缺口一：只注重单词记忆，不注重运用。学生被训练的是"词—义"的连线，而考试考察的是"语境 → 意义 → 表达"的完整链条。于是常见的一幕是：词表背了很多遍，一到阅读里认不出它的具体义项、一到写作里用不出来。一词多义与熟词僻义（screen 名词是"屏幕"、动词是"筛查"）尤其吃亏——背过这个词，却在句子里读不懂。

缺口二：缺乏定制化的语境。主流工具提供的是通用词表，而不是与"你正在面对的材料""你自己的生活"绑定的语境。而学生真正要对付的语境恰恰是很具体的：

语境来源学生的真实处境通用词表 App
考题中的语境这张卷子里的这个词，考的是哪个义项？常和哪个搭配一起考？只给最常见的一两条释义
日常生活中的语境想表达"我昨天遇到的事"这类属于我自己的内容，该用哪个词、怎么搭？没有对应入口
学生自己经历的语境我感兴趣的话题（体育、游戏、科技）里出现的表达不可能覆盖

1.3 学校已经在做"提炼"，但它的覆盖是有边界的

值得注意的是：帮助学生提炼这件事，学校其实一直在做——几乎所有学校都会采用"英语提炼"的形式辅助学生记单词：老师针对卷子与考题，提炼出其中的单词、词组与考点。这是非常有效的做法，但它的边界也很清楚，而这条边界恰恰暴露了学生自主学习时最大的空缺：

学校的提炼学生自己刷题 / 做阅读时
谁做提炼老师（专业、有经验）没有人——学生只能自己查词、凭感觉判断该背什么
面向谁面向大众：要照顾班里不同层次的同学，取舍偏保守、偏共性本应面向我自己：只看我没掌握的、我需要的
覆盖材料老师选定并讲解的材料学生手上任何材料（自己买的卷子、感兴趣的外刊）

一句话概括这个空缺：老师的提炼是"一对多"的，而学生自主学习时需要的是"一对一"的——但一对一的成本，老师付不起。

1.4 我们的选择：把"提炼"交到学生自己手里

本软件要做的不是又一个背单词 App，而是把"提炼"这一步从老师手里，变成学生自己就能随时完成的工具：

  • 输入即提炼：粘贴文本、拍照、传 PDF/Word——用学生手上任何材料（课内课文、自己的卷子、感兴趣的外刊），由本机大模型结合语境提炼出这篇材料里该学的生词、词组、作文金句、搭配与语法
  • 个性化分层：按"考纲词书 × CEFR 等级 × 个人历史掌握"三层过滤，并识别熟词僻义；定位是学生的自助自检——只看自己没掌握的，效率优先
  • 闭环到记忆：候选自评 → 中英双向默写（含原文例句挖空）→ SM-2 间隔复习 + 掌握三分 + 每日自测
  • 不止于提炼：软件还包含聊天（AI 语伴纠错、作文批改）与阅读模块，除听力外基本覆盖英语学习的各个环节，适配现代学生的使用习惯
  • 用兴趣换内驱力：英语学习中大量内容本身枯燥，而学生可以挑选自己感兴趣的题材作为阅读材料——同一套提炼与记忆机制，读的是你喜欢的东西，学习内驱力自然不同

1.5 选择全本地模型：一个被忽视的学校诉求

学校对题目、试卷、作文这类资源是有隐私顾虑的——这正是许多优质资源"不敢上云"的原因。本软件把模型与数据全部放在本机：不发起任何上传请求，学习数据只存在本地；在机房不联网、校园网受限的场景下也能正常使用。这不是技术上的保守，而是针对真实使用场景的设计选择。

1.6 作者的视角

我自己走完了高中三年的英语学习。回头看，真正吃掉时间、也最让我无力的环节其实不是"背"，而是没人替我做提炼。

在学校里，老师会针对卷子和考题提炼单词、词组与考点——这个方法很有效，但它是面向全班的，要照顾不同层次的同学；而当我课后自己刷题、自己做阅读的时候，就没有人再为我做这件事了：一篇陌生材料摆在面前，哪些词是我真正该攻的、这个词在这句里是哪个义项、它和哪个搭配一起考，全得自己判断，效率很低。

所以我结合 AI 做了这款软件，想解决的正是这个空缺：让每个学生都能给自己做"一对一"的提炼——把手上任何材料丢进去，由本机模型结合语境提炼、按自己的水平分层，再自检、默写、按计划复习。它不需要替代老师，而是补上"老师不在场时"的那一段。

我也特意让它不只做提炼：聊天与阅读也做了进来，除听力外的环节都能覆盖；并允许学生自选感兴趣的题材当阅读材料——因为英语学习最难的不是方法，而是愿意持续下去。

2.2 关键设计决策

决策理由
端侧模型而非云 API目标场景（学生日常学习）里隐私与"随时可用"是硬需求；Gemma 4 已改为 Apache-2.0，商业与再分发无阻碍
llama.cpp 而非 Ollama可直接挂 mmproj 做多模态（拍照识别），且能塞进单文件夹一体化分发；Ollama 保留为可选回退路径
Node 零依赖后端不需要 npm install，clone 下来就能跑——把"陌生人 5 分钟能用"作为一等目标
词书过滤用规则而非模型"这个词是不是考纲词"必须确定性、可复现；模型只负责语言理解，判断交给规则层与词书数据
学习记忆放浏览器学生数据零落盘、零上传；代价是清浏览器数据即重置（已在文档中明示）

2.3 三条输入链路

  1. 文本：直接粘贴，长文（>2200 字符）自动切块合并
  2. 照片：RapidOCR 快路径（印刷体 ~1–2 秒）→ 质量不足自动切内置视觉模型（复杂版面 / 手写）→ 双保险
  3. 文档：PDF（文本型直接抽字 / 扫描版逐页渲染识别）、Word、txt；识别文字回填输入框，可编辑确认后再提炼

2.4 可移植性（面向"陌生人能跑"）

后端对 Python 采取降级优先的探测链：内嵌 macOS Python → 内嵌 runtime\python → ES_PYTHON 环境变量 → 本机候选 → python3/python； 全部找不到时，照片 OCR 与文档解析自动降级，粘贴文本与视觉模型链路不受影响。模型与引擎不随仓库分发，由 tools/ 下脚本按 sha256 逐字节校验从上游获取；无模型时软件仍可启动（界面、词书、默写、记忆层全部可用）。

2.5 交付形态：封装桌面软件，开箱即用

本项目最终以封装好的桌面软件交付，而不是一个"装了环境才能跑"的源码包——这是面向学生与老师的第一原则。

用户以为要做的事实际情况
安装 Node.js / Python不需要——分发包内已内置运行时（runtime\win\node.exe、runtime\python\python.exe）
下载 AI 模型不需要——约 3.9 GB 的 Gemma 4 权重与视觉模块已随包提供
安装推理引擎、配环境变量不需要——llama.cpp 引擎与所需运行库已在包内
用命令行启动不需要——Windows 双击 英语背诵工具.exe（WebView2 桌面壳）；macOS 双击 英语背诵工具.app
联网激活 / 注册账号不需要——全程离线，无账号、无 API Key、无调用费用

分发包为单文件夹、免安装（约 6.9 GB）：app/（服务与前端）· engine/ 与 app/llama/（推理引擎）· models/（模型权重）· runtime/（内置 Node / Python 运行时）· data/（词书）· scripts/（OCR / PDF / 词书构建脚本），并含 Windows 启动器 英语背诵工具.exe 与 macOS 英语背诵工具.app。

同时，源码以 Apache-2.0 开源：开发者可 clone 仓库自行构建，仓库内附模型与引擎的获取脚本（含 sha256 逐字节校验与断点续传）；未安装 Python、未放模型时软件仍可启动并自动降级运行（界面、词书、默写、记忆层全部可用）。

为什么仓库里给的是源码，而不是那个安装包？因为封装包内包含约 3.9 GB 的模型权重，超出代码托管平台对单个文件的硬限制（GitHub 为 100 MiB），无法进入代码仓库——这是体积约束，不是功能缺失。因此本项目采取双轨交付：开源仓库提供完整、可直接运行的源码与一键获取脚本（满足评审对"完整可运行代码"的要求）；封装桌面版因体积原因另行分发。换言之——评审与开发者拿到的是源码，学生与老师拿到的是软件。

三、应用场景

本项目全部场景的共同点是：把"提炼"交到学生自己手上，材料不限、分层按己、全程离线。

场景具体用法与价值
① 课后自学自检
（主场景）		 学校课堂上，老师会针对卷子与考题提炼单词、词组与考点——但那是面向全班的。真正的空缺出现在课后：学生自己刷题、自己做阅读时，没有人再为他提炼。本软件填的就是这一段：把手上任何材料（当天的卷子、课外的文章、拍下来的一页书）交给本机模型，按自己的水平分层提炼，再自检、默写、按计划复习。课堂上跟老师，课后跟自己。
② 考前定向复习 不再从第一页开始刷词表——按"我还没掌握的"筛：已掌握的词自动掠过（掌握三分），错过的词优先复现（错题池），SM-2 把复习量摊到每天（≤30 题的每日自测）。把有限的时间压到真正薄弱的地方。
③ 兴趣驱动的自主阅读 英语学习里大量内容本身是枯燥的。学生可以挑选自己感兴趣的题材（体育、科技、游戏、喜欢的领域）作为阅读材料，同一套"提炼 → 默写 → 记忆"机制照常运转——读的是自己喜欢的东西，学习内驱力自然不同。这也是软件同时做了阅读与聊天（AI 语伴纠错、作文批改）模块的原因：除听力外，英语学习的各个环节都能在一个工具里完成。
④ 无网 / 隐私敏感环境 校园网受限、机房不联网、家庭宽带不稳的场景下依然完整可用；学校的题目、试卷、作文属于敏感资源，本软件不发起任何上传请求，数据只在本机——这让"愿意用"不再需要以"交出去"为代价。
⑤ 教师与家长视角
（部分实现）		 老师选定的材料可一键生成清单、复制成文本发到班级群，学生导入同一篇即可对齐；家长可通过导出看到掌握情况。如实说明：班级管理与布置功能的老师端尚未实现，已列入后续规划。

四、创新点（对比式说明）

4.1 把老师"一对多"的提炼，变成学生可自助的"一对一"

已有方案：学校普遍采用"英语提炼"帮助记单词——老师针对卷子与考题提炼单词、词组与考点；市面 App 则提供通用词表。
不足：老师的提炼面向大众（要照顾班里不同层次的同学，取舍偏保守、偏共性），且只覆盖老师选定的材料；而学生自己刷题、自己做阅读时，没有人替他提炼。通用词表则缺乏定制化语境——考题中的语境、日常生活中的语境、与学生自身经历相关的语境，它都给不了。
本项目：用端侧模型把同等质量的语境化提炼交给学生本人——材料任意（课文 / 卷子 / 外刊 / 拍照）、分层按己（考纲词书 × CEFR × 个人历史掌握 + 熟词僻义识别）、定位是自助自检，只看自己没掌握的。它不替代老师，而是补上"老师不在场时"的那一段。

4.2 端侧推理：数据不出机器，断网可用，零调用费用

已有方案：同类 AI 学习工具普遍把文本上传云端模型。
不足：学生作文、试卷、错题属于敏感数据；断网即不可用；按 token 计费，长期使用成本高。
本项目：Gemma 4（Apache-2.0）经 llama.cpp 在本机推理，实测 8–20 秒/篇（RTX 5060 Laptop 8GB）；无网络、无 API Key、无调用费用，学习数据只存本地浏览器。对学校而言，这是"敢用"的前提。

4.3 分层可解释、数据可复现

已有方案：让模型直接输出"本课生词"，或使用来源不明的词表。
不足：结果不可解释、不可复现，无法对应考纲差异，且容易漏掉"认识但新义项没学过"的词。
本项目：① 归属判定交给规则层而非模型——全文词与主词书机械比对，标注"考纲 / 拓展"；② CEFR 等级 + 年级门槛过滤；③ 熟词僻义识别（一词多义时，低义项已掌握而高义项未学则保留）；④ 词书全部由 scripts/ 从明确许可的公开数据源重建，且与 ECDICT 独立数据源交叉验证重合 95.4%——每个词都能解释"为什么它在清单里"。

4.4 覆盖"除听力外"的完整闭环，且以开源形式可复用

已有方案：多数 AI 学习工具止于"生成清单"。
本项目：提炼 → 候选自评 → 双向默写（AI 容错判卷、原文例句挖空）→ 错题池 → SM-2 间隔复习 + 掌握三分 + 每日自测；并含阅读与聊天（AI 语伴纠错、作文批改）模块——除听力外基本覆盖英语学习的各个环节。整套记忆内核与词书构建流水线均以 Apache-2.0 开源，其他教育类项目可直接复用。

4.5 用兴趣换内驱力

已有方案：学习材料与词表由平台或教材预先指定。
不足：大量内容与学生个人兴趣无关，靠打卡维持，难以长期坚持。
本项目：学生可自选感兴趣的题材作为阅读材料，同一套提炼与记忆机制照常运转——把"要我背"变成"我想读"。学习最难的不是方法，而是持续。

4.6 封装交付：不写代码的人也能直接用

已有方案：多数同类开源 AI 项目以"源码 + 安装说明"交付，使用者需要自己装运行时、配环境、下模型——这直接把最需要工具的学生与老师挡在门外。
本项目：以封装好的桌面软件为交付形态——分发包内已内置 Node / Python 运行时、约 3.9 GB 的模型权重、llama.cpp 引擎与全部词书，单文件夹免安装、双击即用、全程离线、无需账号；Windows 提供 WebView2 桌面壳（英语背诵工具.exe），macOS 提供原生 .app。源码同时以 Apache-2.0 开源，开发者可自行构建并复用其记忆内核与词书流水线。
